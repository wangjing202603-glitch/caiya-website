> **本节要点**：产值日报改造第一关是"谁录数据"不是"用什么工具"；从 Python EXE 转向钉钉宜搭 + Python + 钉钉机器人；车间文员录产量，会计只管算和推。

## 痛点：老板每天要，会计每天拼

老板每天早 9 点要看一份数据：昨天每个车间、每个订单生产了多少。这份数据散在 3 个地方——车间文员的产量记录、订单系统、人员出勤。**资金会计每天手工拼这份日报，要 2 小时**。

我一开始的反应跟大多数人一样：写个 Python 工具，自动跑。

## 第一个坑：以为写个工具就行

我做了第一版方案：Python EXE 单机工具，跟出纳工具一个套路——车间把产量导成 Excel，工具读进去算产值。

做完发现**根本跑不通**：

1. **车间文员不会导 Excel**——她们习惯了纸笔和微信群发
2. **产量数据每天散落在 5 个车间**——没有统一格式
3. **会计还是要挨个催、挨个整理**——工具省的时间被催数据耗光

工具本身没问题，**数据源头没人能稳定喂**才是死结。

## 真正的第一关：谁来录数据

我重新想这件事。产值日报的数据链是：

```
产量（车间产生）→ 单价（财务掌握）→ 产值（算出来）→ 日报（推给老板）
```

关键决策：**产量这一步，让谁来录？**

- 让会计录？会计不在车间，要挨个问，回到手工拼
- 让车间文员录？她们是数据源头，但要用她们能上手的工具
- 让系统自动？订单系统有部分数据，但工序产量没有

结论：**车间文员录产量**，但要给她们一个简单到不用培训的工具。

## 方案转向：钉钉宜搭 + Python + 钉钉机器人

最终架构（v1.4）：

| 角色 | 工具 | 职责 |
|---|---|---|
| 车间文员 | **钉钉宜搭**（手机表单） | 每天录产量、出勤 |
| Python 端 | Python 脚本 | 含单价表，算产值 + 生成日报消息 |
| 钉钉机器人 | 自定义机器人 | 把日报推送给老板 |

数据流：
```
车间文员手机录产量（宜搭）
   ↓
Python 拉宜搭数据 × 单价表 → 算产值
   ↓
生成 markdown 日报（按老板截图样式）
   ↓
钉钉机器人推送到老板群
```

## 为什么不用一个 Python 工具搞定

因为**数据来源是多人协同产生的**。出纳工具能 EXE 化，是因为数据来自银行（单一外部系统导出）。产值日报的数据来自多个活人录入，必须给协作工具——这就是钉钉宜搭的位置。

我们沉淀的判断框架：

| 数据来源 | 工具形态 |
|---|---|
| 外部系统导出（银行/金蝶） | Python EXE 单机 |
| 多人录入协同产生 | 钉钉宜搭 + Python 汇总 |

## 关键设计决策

1. **单价不进宜搭**：宜搭没有"单价字段"（车间文员不该看到单价），单价在 Python 端维护
2. **订单主数据财务管**：订单号、SKU、合同交期由资金会计维护；车间文员只录产量
3. **日报按老板截图样式渲染**：不是给会计看的表，是给老板看的 markdown 消息
4. **人员系统单独建**：花名册 + 每日出勤 + 离职记录，跟产量解耦

## 实测效果

| 指标 | 改造前 | 改造后（设计） |
|---|---|---|
| 会计每日耗时 | 2 小时 | 15 分钟（查异常） |
| 数据准确率 | 依赖会计记忆 | 源头录入，可追溯 |
| 老板收到时间 | 上午 11 点 | 早 8 点自动 |

工具还在车间文员培训阶段，未完全投产，但方向已验证。

## 你怎么用

如果你的日报/周报卡在"数据散落多人"，先别写工具，先问 3 个问题：

1. **数据源头是谁产生的**？（产量=车间、销售=业务、出勤=HR）
2. **给她们什么工具录最简单**？（手机表单 > Excel > 纸笔）
3. **单价/规则这类敏感数据谁管**？（不能暴露给录数据的人）

3 个问题答完，工具形态自己就出来了。
