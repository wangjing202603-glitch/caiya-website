> **本节要点**：付款后回单发群是高频手工动作；3 银行（宁波/民生/中信）PDF 回单 OCR + 自动命名（收款公司-金额）+ 钉钉机器人推送；已投产使用。

## 痛点：一张张截图发采购群

我们付款后，采购同事要知道"哪笔付了、付了多少、回单长什么样"。原来的流程：

1. 出纳在网银下载付款回单 PDF
2. 截图
3. 发到采购钉钉群
4. @相关采购说明"这是付给 XX 的"

每天几十笔付款，光这个动作就耗 1 小时。**纯手工、纯重复、纯数据搬运**——典型的该被 AI 干掉的活。

## 解决方案：OCR + 机器人

我们做的工具 v4.0，分两个阶段：

### Phase 1：自动 OCR 命名
- 输入：银行网银下载的付款回单 PDF（3 家银行：宁波、民生、中信）
- 处理：pdfplumber 提取文本 + PyMuPDF 裁剪图片，解析出**收款公司、金额、用途、日期**4 字段
- 自动过滤：非货款的（ETC/内部转账/个人/政府）自动剔除
- 输出：每张回单命名为「**收款公司-金额.png**」

### Phase 2：钉钉机器人推送
- 命名好的回单，自动推送到采购钉钉群
- 用企业应用 + sampleFile 方案（文件可下载高清原图）
- 不依赖第三方图床（数据安全）

## 3 家银行的坑

3 家银行回单 PDF 格式完全不同：

| 银行 | 格式特点 | 坑 |
|---|---|---|
| 宁波银行 | 客户回单，有下载按钮 | 新版"客户回单"格式重写，要兼容旧版 |
| 民生银行 | 全新解析 | 字段位置与别家完全不同 |
| 中信银行 | 老格式 | 保留原有解析 |

测试：57 笔回单（宁波 30 + 民生 12 + 中信 15），货款识别 100% 准确。

## 一个命令搞定

工具合并成一条命令：

```bash
python push_receipts.py --ocr-only   # 只 OCR + 命名
python push_receipts.py --push-only  # 只推送已命名的
python push_receipts.py              # 默认：先 OCR 后推送
```

出纳每天付款完，跑一条命令，回单自动发采购群。

## 附加功能：@机器人查水单

采购想查"上个月付给 XX 的回单"，直接在群里 @机器人 + 供应商名：

```
@付款回单通知 XX货代
```

机器人搜索最近 30 天回单，把匹配的发到群里（最多 5 个）。采购不用再翻聊天记录。

## 数据安全的关键决策

我们没用第三方图床（如 SM.MS）。原因：

- 付款回单含供应商名、金额、银行账号——**敏感**
- 第三方图床数据安全不可控

最终方案**全在钉钉体系内**：企业应用 sampleFile 上传，采购群内分发，不外泄。

## 实测效果

| 指标 | 改造前 | 改造后 |

| 每天发回单耗时 | 1 小时 | 1 条命令（5 分钟） |
| 采购查回单 | 翻聊天记录 | @机器人 3 秒 |
| 错发/漏发 | 月均 3 次 | 0 |

工具已交接给应付会计（工作交接：原资金会计 → 应付会计），稳定运行。

## 你怎么用

要复用这个工具，关键变量：

1. **你们用哪几家银行**——每家要写 OCR parser
2. **推送渠道**——我们用钉钉，你也可以飞书/企业微信（API 类似）
3. **过滤规则**——哪些算"该发采购群"，每家不同

交付包里，3 家银行 parser 是现成的，新增银行按同样模式写一个就行。
