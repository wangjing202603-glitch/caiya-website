> **本节要点**：数电票在电子税务局开具；交付是 XML + PDF；归档要存 XML 原件；入账以 XML 为准。

## 数电发票 vs 传统纸质票

| 维度 | 传统纸质/税控盘 | 数电票 |
|---|---|---|
| 开票设备 | 税控盘/Ukey | 任意联网设备 |
| 开票渠道 | 开票软件 | 电子税务局网页/APP |
| 票面载体 | 纸质 + PDF | XML 数据 + PDF 版式 |
| 作废/红冲 | 复杂 | 线上红冲 |
| 归档 | 纸质 + 电子 | XML + PDF |

数电票是**趋势**，2026 年大部分企业已切换。

## 开具流程

1. 登录**电子税务局** → 【我要办税】→【开票业务】
2. 选发票类型：普通发票 / 增值税专用发票
3. 填购买方信息（名称、统一社会信用代码、地址电话、开户行）
4. 填商品/服务明细（名称、数量、单价、税率、金额）
5. 选择交付方式（邮件/二维码/下载）
6. 提交开具，系统分配**发票号码**（20 位）

## 交付：怎么给客户

数电票交付方式（按推荐度）：

1. **邮件交付**——输入客户邮箱，系统直接发 PDF + XML
2. **二维码**——客户扫码自行下载
3. **下载后转发**——下载 PDF + XML，微信/邮件发给客户

客户需要 **PDF 看票面**，**XML 入账**。两者都要给。

## 归档：财务怎么存

依据《关于规范电子会计凭证报销入账归档的通知》（财会〔2020〕6 号）与《会计档案管理办法》（财政部 国家档案局令第 79 号）：

- **必须保存 XML 原件**——这是唯一法律认可的电子原件
- PDF 仅作展示用，**不能**作为唯一归档
- 保存期限：**30 年**（会计档案最低期限）
- 存储介质：可靠存储 + 异地备份

实操：建一个目录结构
```
发票归档/
├── 2026/
│   ├── 07月/
│   │   ├── 销项/           （开的）
│   │   │   ├── 2440000000000000001.xml
│   │   │   └── 2440000000000000001.pdf
│   │   └── 进项/           （收的）
```

## 入账要点

- 数电票入账，**以 XML 解析出的结构化数据为准**，不以 PDF 视觉为准
- 进项税抵扣，需在电子税务局【抵扣勾选】里确认
- 重复报销风险：数电票可无限复制，建议用发票查重工具或台账

## AI 怎么帮你

- **批量解析 XML**：Python + AI 读出买方/卖方/金额/税额/明细，自动登账
- **查重**：用发票号码做主键，AI 比对台账找重复
- **异常检测**：AI 找出"税率不符、金额异常、购买方名称异常"的票

## 常见坑

- 只存 PDF 不存 XML——不合规
- 用截图报销——数电票没有"原件截图"概念，必须 XML
- 忘记勾选抵扣——进项税白白浪费
- 红冲后原票还在系统——红冲要关联原票号

我自己每月会把 XML 按月归档一次，每季度抽查 10 张核对文件完整性——不抽查等于没归档。
