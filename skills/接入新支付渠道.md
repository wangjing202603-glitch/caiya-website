# 技能：接入新支付渠道

> 适用：工程负责人
> 目标：把一个新支付渠道（如银联 / PayPal / 数字人民币）按"统一接口 + 沙箱验证 + 灰度"流程接进来。

## 1. 触发场景

- 业务需要新渠道（海外用户、银联、京东 / 数字人民币）
- 老渠道下线需要替换
- 渠道 A 临时不可用需要双跑

## 2. 前置

- 主理人 / 财务批准
- 已获取商户号 + 凭据（沙箱）
- 阅读 [`docs/03-rules/支付与对账.md`](../docs/03-rules/支付与对账.md)

## 3. 流程

### 3.1 准备凭据

1. 沙箱申请
2. 凭据存 `secrets/`（不入 Git）
3. 同步到 Vercel Preview / Production 环境变量
4. 文档化在 [`templates/支付集成对接单.md`](./templates/支付集成对接单.md)

### 3.2 实现适配器

新建 `lib/payment/<channel>.ts`，实现：

```ts
interface PaymentProvider {
  name: 'wxpay' | 'alipay' | '<new>'
  createOrder(input): Promise<CreateOrderResult>
  queryOrder(orderNo): Promise<OrderStatus>
  refund(input): Promise<RefundResult>
  verifyWebhook(req): Promise<WebhookEvent>
}
```

要求：

- 详细注释 + 类型
- 错误码映射到 [`docs/03-rules/API-设计.md`](../docs/03-rules/API-设计.md) 的统一错误码
- 日志包含 `channel / orderNo / action`，敏感字段脱敏
- 单元测试（mock 渠道 API）

### 3.3 注册到工厂

在 `lib/payment/index.ts` 注册新 channel：

```ts
const providers: Record<string, PaymentProvider> = {
  wxpay: new WxpayProvider(),
  alipay: new AlipayProvider(),
  <new>: new NewProvider(),
}
```

### 3.4 数据库

- `orders.channel`：枚举加新值
- 迁移：`pnpm prisma migrate dev --name add-payment-channel`
- `Order.channel` 与 `PaymentProvider.name` 一致

### 3.5 前端

- `/pricing` 与 `/account/orders` 的 channel 列表加新渠道
- 图标 + 名称 + 简短说明

### 3.6 沙箱联调

1. 部署到 staging
2. 走通：
   - 创建订单 → 支付（用沙箱测试号）→ webhook
   - 主动查询
   - 退款
   - 异常（验签失败 / 重复回调 / 网络中断）
3. 截图 / 录屏作为 PR 附件

### 3.7 灰度

- 内部员工 100% 走新渠道 1 周
- 随机 5% 用户 → 2 周
- 错误率 / 成功率稳定 → 100%

### 3.8 文档

- [`docs/03-rules/支付与对账.md`](../docs/03-rules/支付与对账.md) 加章节
- ADR：`<ADR-编号>-<channel>.md`
- [`memory/历史经验.md`](../memory/历史经验.md) 记录坑点

## 4. 验收

- [ ] 沙箱联调通过（截图齐全）
- [ ] 单元测试覆盖率 ≥ 80%
- [ ] webhook 验签失败 5 次以上有告警
- [ ] 退款链路跑通
- [ ] 对账脚本支持新渠道
- [ ] 文档同步更新
- [ ] ADR 签字

## 5. 反模式

- ❌ 跳过沙箱直接上线
- ❌ 凭据硬编码
- ❌ 与现有 `PaymentProvider` 接口不一致
- ❌ 没有 webhook 验签
- ❌ 没有幂等
- ❌ 没有错误日志
