# 技能：创建知识库文章

> 适用：所有人（人类 + Agent）
> 目标：让一篇新文章从选题到上线有完整可复用的流程。

## 1. 触发场景

- 新增一篇 KB 文章
- 把已有内部分享 / 笔记改写成 KB 文章
- 团队外投稿（先走 [`docs/03-rules/内容审核.md`](../docs/03-rules/内容审核.md) 的投稿流程）

## 2. 前置

- 阅读 [`docs/02-design/内容样式指南.md`](../docs/02-design/内容样式指南.md)（必读）
- 阅读 [`memory/术语表.md`](../memory/术语表.md)
- 准备选题（来自 `content/kb/_index.json` 的分类，或新提议）

## 3. 流程

### 3.1 选题登记（5 分钟）

1. 在 GitHub Discussions → 「内容选题」板块开帖
2. 模板：
   - 标题
   - 目标读者（哪个 Persona）
   - 用户痛点（一句话）
   - 计划大纲（H2 x 3~7）
   - 拟引用政策 / 数据来源
   - 估计写作时长
3. 维护者确认 → 给个 Issue 编号

### 3.2 拉分支（1 分钟）

```bash
git checkout develop
git pull
git checkout -b kb/<category>/<slug>
```

`<category>` 与 `<slug>` 用拼音，kebab-case。

### 3.3 创建文件（5 分钟）

路径：`content/kb/<分类>/<slug>/index.mdx`（同目录可放 `assets/`）

拷贝 [`templates/kb-article.mdx`](./templates/kb-article.mdx) → 填 Frontmatter。

### 3.4 写正文（2~6 小时）

- 严格按内容样式指南
- 关键事实 / 政策 / 数据先列出来，再写
- 关键事实可链接到 [政策法规库] / 政府官网
- 公式用 KaTeX；图表用 Mermaid 或图片

### 3.5 自检（30 分钟）

逐项打勾：

- [ ] Frontmatter 全填（title/description/category/tags/author/reviewers/status/access/createdAt/updatedAt/verifiedAt/version）
- [ ] H1 唯一，全文 0 个 H1
- [ ] H2 3~7 个
- [ ] 标题 ≤ 30 字
- [ ] description ≤ 120 字
- [ ] 关键政策 / 数据带出处链接
- [ ] 内部链接用 `/kb/...` 相对路径
- [ ] 图片有 alt，敏感信息打码
- [ ] 表格 / 列表 / 代码 / 公式均按指南
- [ ] 文末有"本节要点"+ 相关推荐占位
- [ ] 至少 1 名 SME 在 reviewers 中

### 3.6 提 PR（5 分钟）

使用 [`templates/PULL_REQUEST.md`](./templates/PULL_REQUEST.md)，包含：

- 关联的 Issue / Discussion
- 关键修改点
- SME 评审结论
- 截图（如有 UI 改动）
- 风险

### 3.7 评审（1~3 天）

- 编辑评审：表达 / 排版 / 链接
- SME 评审：政策准确性 / 数据出处
- 根据 review 修订 → 重 push

### 3.8 合入与发布

- 通过后 squash merge → `develop`
- 主干 nightly 自动构建 + 部署到 preview
- 主理人复核 → 改 `status: published` → 合入 `main`
- 30 天后系统自动提示"待核验"

## 4. 验收

- [ ] preview 站能正常打开
- [ ] 移动端排版无错位
- [ ] 暗色模式无错位
- [ ] 锚点 / TOC 工作正常
- [ ] 代码块"复制"按钮可用
- [ ] "是否有用"反馈能写入
- [ ] SEO meta / OG 完整
- [ ] SME 评审签字
- [ ] 编辑复核签字

## 5. 反模式

- ❌ 复制别人原创内容
- ❌ 标题党 / 营销话术
- ❌ 不标出处的"经验之谈"
- ❌ 一篇写 5000+ 字不拆
- ❌ 涉及具体个人的"避税方案"
- ❌ 直接用个人 / 真实客户的合同 / 发票做截图
