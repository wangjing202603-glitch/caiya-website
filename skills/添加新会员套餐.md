# 技能：添加新会员套餐

> 适用：主理人 + 运营 + 工程
> 目标：让"加一个套餐"这件事对所有渠道（数据库 / 前端 / 支付 / 落地页）保持一致。

## 1. 触发场景

- 上线新套餐（如"团队版""年度版"）
- 调整现有套餐价格 / 权益
- 季节性促销（"双 11 8 折"）

## 2. 前置

- 主理人批准（写在 `memory/未决问题.md` 关闭项）
- 财务 + 法务确认（如涉及开票 / 自动续费）

## 3. 流程

### 3.1 定义 Plan

1. 在 `prisma/seed.ts` 添加 / 修改 `Plan`：
   - `code`：`team_yearly`（kebab-case）
   - `name`："团队年度版"
   - `price`：分（`int`），如 `99900` = ¥999.00
   - `durationDays`：`365`
   - `features`：JSON 数组，每条 ≤ 30 字
   - `sort`：显示顺序
   - `highlight`：是否在 `/pricing` 高亮

2. 跑 `pnpm prisma migrate dev --name add-team-yearly-plan`

3. 在 staging 验证

### 3.2 更新 `/pricing` 页面

- 复制 `PlanCard` 组件，按需传 `plan` 数据
- 改动后跑视觉回归（如启用 Playwright）
- 移动端 / 暗色 / 焦点态都要看

### 3.3 支付渠道配置

- 微信支付商户后台：一般不需要为套餐单独配（统一下单接口用动态金额）
- 支付宝：同上
- 特殊活动（如折扣）：用优惠 ID / 立减接口，单独配

### 3.4 文档 / 站内通知

- 更新 [`docs/01-vision/产品愿景.md`](../docs/01-vision/产品愿景.md) 的"价格档位"
- 发一封邮件给已有会员
- 公众号发推
- 站内 `/pricing` 顶部加横幅"限时 8 折"

### 3.5 上线

- 合并 PR → 自动部署到生产
- 5 分钟 smoke test：注册 → 选新套餐 → 支付 → 会员开通
- 群内同步

## 4. 验收

- [ ] DB 中 `Plan` 已新增，迁移已应用
- [ ] `/pricing` 显示新套餐，价格与权益正确
- [ ] 新下单 → 微信 / 支付宝能正常创建订单
- [ ] 支付成功 → 会员状态正确（`status=active`，`endAt=now+durationDays`）
- [ ] 续费按规则生效（不重复扣款）
- [ ] 邮件 / 公众号 / 站内通知均已发
- [ ] 财务对账无异常

## 5. 反模式

- ❌ 改动价格不写 ADR
- ❌ 临时改价不通知老用户
- ❌ 自动续费条款没在协议里写清
- ❌ 多个团队成员各改一份（容易漂移）
