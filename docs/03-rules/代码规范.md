# 代码规范

> 最后更新：2026-07-01 · 维护人：@工程负责人
> 所有业务代码必须通过 ESLint + Prettier + `tsc --noEmit` 三关。

## 1. 语言与版本

- TypeScript 5.4+，`strict: true`
- Node 20 LTS（见 `.nvmrc`）
- 包管理：**pnpm**（不用 npm / yarn；CI 与本地必须一致）
- 框架：Next.js 14（App Router）

## 3. 命名

| 类别 | 规则 | 例 |
|---|---|---|
| 文件 | kebab-case | `kb-sidebar.tsx` |
| 组件 | PascalCase | `KbSidebar` |
| 函数 / 变量 | camelCase | `getUserById` |
| 类型 / 接口 | PascalCase | `KbArticle` |
| 常量 | UPPER_SNAKE | `MAX_AI_QUOTA` |
| 布尔 | is/has/can 前缀 | `isMember`, `hasAccess` |
| React Hook | use 前缀 | `useKbSearch` |
| 数据库表 | snake_case 复数 | `kb_articles` |
| 数据库列 | snake_case | `published_at` |
| API 路径 | kebab-case | `/api/ai/chat` |
| 环境变量 | UPPER_SNAKE | `DATABASE_URL` |

## 4. TypeScript

- **禁止** `any`；用 `unknown` + 类型守卫
- **禁止** `// @ts-ignore`；必须用 `// @ts-expect-error <reason>`
- 类型导出用 `export type`，避免 `export { type ... }` 与值混用
- 公共 API 必须有显式返回类型
- 用 `satisfies` 而不是 `as`（必要时）

## 5. React / Next.js

- 默认 RSC（"use client" 越少越好）
- `"use client"` 加在**叶子组件**而不是整页
- `useEffect` 谨慎使用；考虑 server action / event handler
- 不要在 client 组件里 import server-only 模块
- 动态导入用 `next/dynamic`，避免 SSR 不必要的重组件
- 错误边界：每个 (group) 配 `error.tsx`，根 `app/error.tsx`

## 6. 状态管理

- 服务端数据：用 RSC + server action
- 客户端少量状态：`useState` / `useReducer`
- 全局：Zustand（仅在确实需要时）
- **避免** Redux

## 7. 样式

- Tailwind 优先；自定义 CSS 放 `styles/`
- 颜色 / 间距必须用设计令牌；不允许裸值
- 同一元素类名按"布局 → 间距 → 排版 → 颜色 → 交互"顺序
- 条件类用 `clsx` + `tailwind-merge`（封装为 `cn()`）

## 8. 注释

- 业务逻辑"为什么"用注释解释（不要解释"做了什么"）
- 公共 API 用 JSDoc
- TODO 格式：`// TODO(责任人): 描述 - 截止日期`
- 内部算法放 `lib/utils/`，加单元测试

## 9. 导入顺序

```ts
// 1. Node / Next 内置
import { redirect } from 'next/navigation'
// 2. 第三方
import { z } from 'zod'
// 3. @/ 别名
import { cn } from '@/lib/utils'
// 4. 相对
import { KbCard } from './kb-card'
// 5. 类型
import type { KbArticle } from '@/lib/db/types'
```

ESLint `import/order` 强制。

## 10. 错误处理

- API 统一抛 `AppError`（含 `code`、`status`），由 `lib/errors.ts` 处理
- 不在 UI 直接 `console.error`；用 Sentry
- 用户可见的错误用 toast，文案来自 `i18n/zh-CN.ts`

## 11. 测试

- 工具函数 → Vitest 单元
- API → Vitest + supertest
- 关键流程 → Playwright e2e
- 覆盖率目标：工具与业务库 ≥ 80%

## 12. 性能

- 避免在 render 中创建大对象
- 图片用 `next/image`
- 字体用 `next/font`
- 列表虚拟化：> 100 项才用

## 13. 安全（详见 [`安全合规.md`](./安全合规.md)）

- 不用 `eval` / `Function` 构造器
- 不在前端 log 敏感信息
- 第三方依赖定期 `pnpm audit`
- 数据库查询一律参数化（Prisma 默认）

## 14. 工具链

| 工具 | 用途 |
|---|---|
| ESLint + `@typescript-eslint` | 静态检查 |
| Prettier | 格式化 |
| `tsc --noEmit` | 类型检查 |
| Vitest | 单元 |
| Playwright | e2e |
| Husky + lint-staged | 提交前校验 |
| Commitlint | 提交信息规范 |

## 15. Review 关注点

- 是否有设计令牌违规（裸色值、裸 px）
- 是否有 SQL 注入 / XSS 风险
- 错误处理是否完整
- 测试是否到位
- 文档（API 文档、CHANGELOG）是否同步
- 涉及支付的代码是否有沙箱截图
