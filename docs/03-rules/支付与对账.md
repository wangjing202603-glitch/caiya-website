# 支付与对账规范

> 最后更新：2026-07-01 · 维护人：@支付负责人
> 我们支持微信支付 V3 与支付宝，目标是"零掉单、零漏款、零对账纠纷"。

## 1. 接入前提

### 1.1 主体

- **建议**：个体工商户 / 有限公司
- 必备材料：营业执照、法人身份证、对公账户 / 法人结算账户
- 商户号申请周期：5~15 个工作日

### 1.2 凭据

- 微信支付 V3：
  - `mch_id` 商户号
  - `api_v3_key` APIv3 密钥
  - 商户 API 证书（apiclient_cert.pem / apiclient_key.pem）
  - 微信支付平台证书（动态下载）
- 支付宝：
  - `app_id`
  - 应用私钥 / 公钥
  - 支付宝公钥证书

> 凭据放 `secrets/`（不入 Git），生产环境用 Vercel / KMS 注入。

## 2. 接口设计

### 2.1 抽象层

所有支付渠道实现统一接口：

```ts
interface PaymentProvider {
  readonly name: 'wxpay' | 'alipay'
  createOrder(input: CreateOrderInput): Promise<CreateOrderResult>
  queryOrder(orderNo: string): Promise<OrderStatus>
  refund(input: RefundInput): Promise<RefundResult>
  verifyWebhook(req: Request): Promise<WebhookEvent>
}
```

业务代码**只**调接口，不直接调微信 / 支付宝 SDK。

### 2.2 订单状态机

```
        create
   pending ─────► paid
      │   ╲        │
      │    ╲       ▼
      │     ╲   refunded
      │      ╲      │
      ▼       ▼     ▼
   expired  failed  refunded
```

- `pending`：已创建，未支付，30 分钟未付自动 `expired`
- `paid`：收到回调 / 主动查询确认
- `refunded`：管理员 / 用户主动退款（部分 / 全额）
- `expired`：超时未付
- `failed`：创建支付失败

## 3. Webhook 验签

- 微信：验证 Wechatpay-Signature（SHA256 with RSA）
- 支付宝：验证 `sign` 字段 + 公钥验签
- 验签失败 → 401 + 详细日志（包含 traceId）
- 验签成功 → 幂等处理：同一 `transaction_id` 不重复入账

## 4. 幂等与重试

- 所有 webhook 处理函数**必须**幂等
- 失败重试用内部任务队列（PG 表 + cron）
- 重试策略：1min → 5min → 30min → 2h → 12h（最多 5 次）
- 仍失败 → 告警 + 人工介入

## 5. 订单与会员开通

- webhook 验签通过 → 写 `orders.status = paid` + `paid_at`
- 同事务内查 `orders.user_id + plan_id` → 写 / 更新 `memberships`
- 续费：检查 `end_at` 续期 vs 新开 → 按业务规则
- 升级：先按比例退款 → 重新下单
- 降级：下一个周期生效，不退当期

## 6. 对账

### 6.1 日对账

- 每天 09:00 自动跑昨日对账
- 拉微信 / 支付宝账单（CSV / API）
- 与本地 `orders` 比对：
  - 微信有 / 本地无 → 补单（人工确认后入库）
  - 本地有 / 微信无 → 标记异常
  - 金额不一致 → 标记异常

### 6.2 月对账

- 每月 1 日拉上个月账单
- 财务复核 → 出具对账报告
- 归档到 `docs/04-ops/finance/YYYY-MM-对账报告.md`

### 6.3 差异处理

| 场景 | 处理 |
|---|---|
| 微信有 / 本地无 | 客服联系用户 + 补单 |
| 本地有 / 微信无 | 微信侧发起查询 |
| 金额不一致 | 立刻冻结该笔，联系渠道 |
| 重复支付 | 全额退一笔 + 用户告知 |

## 7. 退款

- 用户申请 → 客服审批 → 调 `refund` 接口
- 退款单独立状态机：`pending → success / failed`
- 退款到原支付渠道，3~10 个工作日到账
- 退款不收回已发放的"邀请奖励"等

## 8. 发票

- 用户在 `/account/orders` 申请
- 个人 / 企业的发票抬头校验
- 异步出票，电子普票 / 专票
- 涉及开票：财务月度对账时统一处理

## 9. 监控与告警

- 支付成功率 < 95% → 告警
- 5 分钟内 webhook 失败 > 3 次 → 告警
- 单日对账差异 > 5 笔 → 告警
- 详见 [`../04-ops/监控与告警.md`](../04-ops/监控与告警.md)

## 10. 沙箱与联调

### 10.1 微信支付 V3 沙箱

- 沙箱 API：`https://api.mch.weixin.qq.com/sandboxnew/`
- 沙箱密钥每日重置，需每日获取
- 测试用例：
  - 创建支付 → 扫码（用沙箱专用二维码）→ 回调
  - 主动查询
  - 退款
  - 异常回调（验签失败 / 重复回调）

### 10.2 支付宝沙箱

- 沙箱网关：`https://openapi.alipaydev.com/gateway.do`
- 沙箱买家账号：平台提供
- 测试用例同上

> 涉及支付的 PR 必须附沙箱联调截图。

## 11. 凭据轮换

- APIv3 key：每年至少 1 次
- 证书：到期前 30 天告警
- 私钥泄漏 → 立即吊销 + 重发 + 审计

## 12. 合规

- 展示支付牌照号（支付机构提供）
- 资金不经过平台账户
- 不得自行开展"代收代付"业务
- 用户协议、隐私政策包含"支付条款"小节

## 13. 速查

| 场景 | 规则 |
|---|---|
| 创建订单 | 幂等 key = `userId + planId + yyyyMMddHHmm` |
| 回调失败 | 队列重试 + 告警 |
| 退款 | 客服审批 → 单笔最大 ¥1 万需 2 审 |
| 对账 | 每日 09:00，月度归档 |
