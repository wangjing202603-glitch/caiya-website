# 安全与合规规范

> 最后更新：2026-07-01 · 维护人：@安全负责人
> 我们的产品服务国内财务人群，遵循《网络安全法》《数据安全法》《个人信息保护法》《互联网信息服务管理办法》等。

## 1. 安全原则

1. **最小权限**：用户/服务/角色只给必需的权限
2. **纵深防御**：网络 → 应用 → 数据 多层防护
3. **默认安全**：所有功能默认关闭高风险能力
4. **可审计**：所有关键操作可追溯
5. **数据最小化**：能不收集的就不收集

## 2. 认证与授权

### 2.1 登录方式

- 邮箱 + 密码（已注册用户）
- 邮箱验证码（推荐；阶段 2 启用）
- 手机号 + 验证码
- 微信扫码（开放平台）

### 2.2 密码

- 至少 8 位，含大小写 + 数字
- 用 `argon2id` 哈希
- 不存明文；不返显
- 5 次失败 → 锁定 15 分钟
- 支持重置（邮件链接 24 小时有效）

### 2.3 角色

| 角色 | 权限 |
|---|---|
| `guest` | 浏览公开内容 |
| `member` | 会员内容 + 基础 AI 问答 |
| `pro` | 高级 AI 问答 + 1v1 咨询（阶段 4） |
| `admin` | 后台 / 审核 / 配置 |

### 2.4 中间件

- 边缘层 `middleware.ts`：登录态 / 角色粗筛
- 业务层 handler：具体资源访问检查
- **不**单独信任前端禁用 / 隐藏

## 3. 会话与 Token

- Auth.js + JWT + 旋转 refresh token
- access token 15 分钟，refresh 30 天
- 登出立即失效（黑名单存 Redis，阶段 3 启用）
- 移动端 + Web 同一套机制

## 4. CSRF / XSS / SQL 注入

- **CSRF**：写接口要求 `Idempotency-Key` + `Origin` 校验
- **XSS**：React 默认转义；禁止 `dangerouslySetInnerHTML`（白名单 DOMPurify）
- **SQL 注入**：Prisma 参数化；禁止 `$queryRawUnsafe`
- **模板注入**：MDX 渲染限定白名单标签（`rehype-sanitize`）
- **文件上传**：扩展名 + MIME + magic number 三重校验

## 5. 速率限制与防滥用

- 登录接口：每 IP 5 次 / 5 分钟
- 注册：每 IP 1 次 / 小时
- AI 问答：按用户配额（免费 20/日，会员无限）
- 评论：每用户 10 条 / 小时
- 风控：异常触发图形验证码

## 6. 个人信息保护（PIPL）

### 6.1 收集原则

- 目的明确：每个字段说明用途
- 最小化：能不收不收
- 用户同意：注册 / 提交前勾选

### 6.2 字段分级

| 敏感级别 | 字段 | 处理 |
|---|---|---|
| 高度敏感 | 身份证号、银行卡 | 加密 + 仅展示后 4 位 |
| 敏感 | 手机号、邮箱 | 加密 + 脱敏展示 |
| 一般 | 昵称、头像 | 明文 |

### 6.3 用户权利

- 查询 / 更正 / 删除 / 导出 → 7 个工作日内响应
- 注销账号 → 30 天后物理删除

### 6.4 合规文件

- 《用户协议》`/legal/terms`
- 《隐私政策》`/legal/privacy`
- 《Cookie 使用说明》→ 嵌入隐私政策
- 第三方 SDK 共享清单 → 嵌入隐私政策

## 7. 数据安全

- 传输：全站 HTTPS（HSTS + TLS 1.3）
- 存储：敏感字段 AES-256-GCM
- 备份：异地 + 加密
- 销毁：物理删除 + 介质销毁证明
- 密钥：KMS（阶段 2 后引入阿里云 KMS）

## 8. 支付合规

- 仅与持牌机构合作（微信支付 / 支付宝）
- 商户号实名 + 法人身份证 + 结算账户
- 交易资金 T+1 / T+7 结算到对公账户
- 详见 [`支付与对账.md`](./支付与对账.md)

## 9. 内容合规

- 不发布违反"九不准"的内容
- AI 问答前置"内容仅供学习参考，不构成专业建议"
- 用户生成内容（评论、提问）需审核，详见 [`内容审核.md`](./内容审核.md)
- 建立举报机制（24 小时响应）

## 10. ICP 备案与许可

- 上线前完成：
  - ICP 备案
  - 公安联网备案
  - 经营性 ICP（涉及付费 / 会员）
- 备案号展示在所有页脚

## 11. 第三方依赖

- 引入前查：是否在维护、是否开源协议兼容、是否有已知 CVE
- 关键依赖：锁定版本，每月 review
- 跑 `pnpm audit` + `snyk test`
- 漏洞响应：发现 → 24 小时评估 → 72 小时修复

## 12. 事件响应

- 严重 / 高危事件：1 小时内通报安全负责人
- 72 小时内出初步报告
- 涉及大量个人信息的事件：依规向网信办报告
- 详见 [`../04-ops/事故响应.md`](../04-ops/事故响应.md)

## 13. 培训与文化

- 新成员入职过"安全意识"课
- 每季度一次钓鱼演练
- 工程师每年至少 1 次安全培训

## 14. 速查

| 场景 | 规则 |
|---|---|
| 存储密码 | argon2id，cost ≥ 3 |
| 存储 token | 哈希存数据库 |
| 公开 URL | 不带内部 ID；用 cuid/uuid |
| 配置文件 | `.env` + 控制台，不入 Git |
| 日志 | 脱敏；不打印身份证 / 银行卡 |
| 错误页 | 不暴露堆栈、SQL、内部 IP |
