# 备份与恢复

> 最后更新：2026-07-01 · 维护人：@运维负责人

## 1. 备份对象

| 对象 | 频率 | 保留 | 工具 |
|---|---|---|---|
| PostgreSQL 全量 | 每日 03:00 | 30 天 | Neon 自动 + 跨区手动 |
| PostgreSQL 增量（WAL） | 持续 | 7 天 | Neon PITR |
| OSS 资源 | 实时 | 永久（开启版本控制） | 阿里云 OSS |
| Git 仓库 | 实时 | 永久 | GitHub |
| 应用配置 | 每次变更 | 永久 | Vercel Environment Variables + 1Password |
| 知识库内容（MDX） | 随 Git | 永久 | GitHub |
| 用户上传文件 | 实时 | 永久 | OSS 版本控制 |

## 2. PostgreSQL 备份

### 2.1 Neon 默认能力

- 自动每日全量
- 时间点恢复（PITR）：最近 7 天
- 跨区复制：开启 Neon 跨 region

### 2.2 手动备份

- 重大变更前：`neon branches create --name backup-<timestamp>`
- 导出：`pg_dump` 到 OSS 加密 bucket
- 保留 90 天

## 3. 备份校验

- **每月 1 次**：从最新备份恢复到隔离环境
- 检查：表结构、数据条数、关键用户是否存在
- 校验记录写到 `docs/04-ops/backup-verification.md`

## 4. 恢复流程

### 4.1 应用层

- 误删 / 改坏：Vercel 回滚到上一个绿色部署
- 配置文件：1Password 历史记录 + 重新设置

### 4.2 数据库层

- 数据误改 / 误删：Neon PITR → 选 5 分钟前的时间点
- 整库丢失：跨区副本提升为主
- 重大事故：从 OSS 备份 dump 文件恢复

### 4.3 OSS 资源

- 误删 / 误覆盖：OSS 版本控制 → 选历史版本

## 5. 演练计划

- 季度 1 次：DB 恢复演练（恢复到 staging）
- 半年 1 次：完整灾难恢复（DB + 应用 + OSS）
- 演练结果记录在 `docs/04-ops/finance/dr-drills.md`

## 6. 用户数据删除

- 用户注销：30 天后物理删除（DB + OSS）
- 删除前再确认（手机 / 邮箱）
- 删除记录写 `audit_logs`（保留 5 年）

## 7. 凭据备份

- API 密钥 / 私钥：1Password + 阿里云 KMS
- 1Password 团队账户：双因素 + 紧急访问
- 凭据丢失：联系供应商重发 + 立即轮换

## 8. 速查

| 场景 | 步骤 |
|---|---|
| 误删表数据 | Neon PITR 恢复 |
| 整库丢失 | 跨区副本提升 + 应用回滚到 1.0.0 |
| OSS 文件被改 | 启用版本控制回滚 |
| 配置丢失 | 1Password 恢复 |
