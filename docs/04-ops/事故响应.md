# 事故响应

> 最后更新：2026-07-01 · 维护人：@运维负责人

## 1. 分级

| 级别 | 含义 | 例子 |
|---|---|---|
| P0 | 业务完全不可用 | 全站 5xx、生产 DB 不可用、支付无法收款 |
| P1 | 核心功能受损 | 登录失败、AI 问答全挂、webhook 大量失败 |
| P2 | 部分功能异常 | 单一页面错位、单一支付渠道失败、邮件发送失败 |
| P3 | 不影响主流程 | 文案错误、样式错位、个别用户问题 |

## 2. 角色

- **事件指挥官（IC）**：决策人
- **执行人**：写代码 / 部署 / 操作
- **记录员**：写时间线
- **发言人**：对内 / 对外通知

> 第一个响应者自动成为 IC，直到交接。

## 3. 响应流程

### 3.1 发现（5 分钟内）

- 监控告警 / 用户报告 / 内部测试
- 立即在飞书群开 incident 频道：`#inc-YYYYMMDD-简短描述`
- 拉相关人员

### 3.2 分级与通告（10 分钟内）

- 确认级别
- P0 / P1：电话通知主理人 + 客服
- 更新状态页（阶段 1 末建立：`status.aicaiwu.cn`）

### 3.3 止血（30 分钟内）

- **优先级 1：恢复服务**，不查根因
- 常用手段：
  - Vercel 回滚
  - 关闭问题功能开关（`FEATURE_*`）
  - 限流 / 熔断
  - DNS 切流

### 3.4 根因分析（24 小时内）

- 拉日志 / 监控 / 复现
- 写 RCA（Root Cause Analysis）草稿
- 与当事人 review

### 3.5 修复（72 小时内）

- 写代码修复 + 部署
- 加测试用例防回归
- 加监控告警防再发

### 3.6 复盘（1 周内）

- 团队 review
- 写事故复盘文档（`memory/事故复盘/YYYY-MM-DD-xxx.md`）
- 转化为可执行项 + 负责人 + 截止日期

## 4. 沟通

### 4.1 对内

- 飞书群 incident 频道
- 进度每 30 分钟更新
- 关键决策公开（避免"私下决定"）

### 4.2 对外

- 状态页：实时更新
- 微信公众号：P0 必发
- 客服话术：P0 准备统一答复
- 用户邮件：P0 必发

## 5. 应急手册（Cheat Sheet）

### 5.1 全站 5xx

```
1. 看 Vercel 日志 → 最近部署
2. 最近 1 小时有部署？→ 回滚
3. 没有？→ 看 Sentry 错误
4. 数据库相关？→ 看 Neon Metrics
5. 暂时无法定位？→ 启用只读模式 + 公告
```

### 5.2 支付失败

```
1. 查 webhook 日志
2. 验签失败？→ 切换证书 / 重启应用
3. 渠道侧问题？→ 微信 / 支付宝后台 + 客服
4. 启用备用渠道（双渠道）
5. 受影响订单 → 手工补单
```

### 5.3 DB 不可用

```
1. 看 Neon Status
2. 应用层熔断（503）
3. Neon 不可用？→ 切到跨区副本（需提前演练）
4. 数据损坏？→ PITR 恢复
5. 全丢失？→ 跨区备份恢复
```

### 5.4 AI 问答挂

```
1. 关 FEATURE_AI_CHAT
2. 搜索/详情页继续工作
3. 评估 LLM 供应商问题 → 切换备用
4. 恢复后做命中抽样
```

## 7. 红线

- 不可隐藏事故
- 不可归因于"用户网络问题"
- 不可不写复盘
- 不可在 P0 期间 commit 主干未审代码

## 8. 速查

| 场景 | 第一步 |
|---|---|
| 监控告警 | 5 分钟内 ack + 开 incident 频道 |
| 用户报告 | 内部确认 → 30 分钟内响应 |
| 数据异常 | 立刻快照（pg_dump 到独立 bucket） |
