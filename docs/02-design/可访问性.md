# 可访问性（A11y）规范

> 最后更新：2026-07-01 · 维护人：@设计负责人
> 我们承诺网站对所有人可用，包括使用屏幕阅读器、键盘、辅助技术的访客。

## 1. 目标

- WCAG 2.1 AA 合规
- Lighthouse Accessibility ≥ 90
- 键盘可完成所有核心任务（注册 / 订阅 / 阅读 / 搜索）

## 2. 语义化 HTML

- 每个页面只有 **1 个 h1**
- 标题层级严格 `h1 → h2 → h3`，不跳级
- 列表用 `<ul> <ol>`，不用一堆 `<br>` 模拟
- 按钮用 `<button>`，链接用 `<a>`（不要给 div 加 `onClick`）
- 表单字段必须有 `<label>` 关联

## 3. 键盘

- 所有交互元素必须 `tab` 可达
- 焦点顺序与视觉顺序一致
- 焦点环**始终可见**（不能 `outline: none`）
- 模态打开时焦点进入模态、关闭后回到触发元素
- `Esc` 关闭模态 / 命令面板

## 4. 颜色与对比

- 文字 vs 背景 ≥ 4.5:1（小字）、3:1（大字 ≥ 18pt 或 14pt 加粗）
- 状态信息不能只靠颜色（如"成功"除绿色外要有图标或文字）
- 暗色模式对比度同样满足

## 5. 图片与媒体

- 装饰图 `alt=""`
- 信息图必须有意义的 `alt`
- 复杂图表附文字描述（`aria-describedby` 或正文中说明）
- 视频/音频提供文字稿或字幕

## 6. ARIA

- `aria-label` 用于没有可见文字的图标按钮
- `aria-live="polite"` 用于动态内容（搜索结果、消息、AI 流式输出）
- `aria-current="page"` 用于当前导航项
- 避免"ARIA 滥用"——能用语义标签就别加 role

## 7. 动态内容

- AI 流式输出：每段写入用 `aria-live="polite"` 朗读
- 模态出现时通知屏幕阅读器（`role="dialog" aria-modal="true"`）
- 表单错误：`aria-invalid` + `aria-describedby` 指向错误文本

## 8. 动效

- 检测 `prefers-reduced-motion: reduce`，关闭非必要动效
- 自动播放的视频必须可暂停；不闪烁（避免光敏性癫痫）

## 9. 表单

- 错误信息就近显示，标红 + 文字
- 必填字段 `<span aria-label="必填">*</span>`
- 提交失败时焦点跳到第一个错误字段

## 10. 跳转链接

- 提供"跳到主要内容"链接，键盘 Tab 第一个
- 详情页提供"跳到侧栏" / "跳到目录"链接

## 11. 移动端

- 触控目标 ≥ 44×44 px
- 旋转屏幕内容不丢失
- 防止误触（按钮间距 ≥ 8px）

## 12. 测试

- 每个 PR 跑：
  - `axe` 自动检测（`pnpm test:a11y`）
  - 键盘走查脚本（Playwright `test/keyboard.spec.ts`）
- 每个版本手动用：
  - VoiceOver（macOS / iOS）
  - NVDA（Windows）
  - TalkBack（Android）
- 至少 1 名团队成员使用过屏幕阅读器测试核心任务

## 13. 验收清单（每页必检）

- [ ] 标题层级正确
- [ ] 焦点环可见
- [ ] 颜色对比度达标
- [ ] 图片有 alt
- [ ] 按钮 / 链接语义正确
- [ ] 表单字段有 label
- [ ] 键盘走查无卡点
- [ ] axe 无 critical / serious 违规
