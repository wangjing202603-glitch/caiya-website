# 技能：发布新版本

> 适用：主理人 + 工程负责人
> 目标：让每次发版可追溯、可回滚、可观察。

## 1. 触发场景

- 累计一批 feature / fix 准备发布
- 营销节点（双 11、月初）需要新功能
- 安全补丁 hotfix

## 2. 流程

### 2.1 准备

1. 确认 [`CHANGELOG.md`](../CHANGELOG.md) 顶部"Unreleased" 段已整理
2. 跑全量 CI（`pnpm lint && pnpm test && pnpm typecheck && pnpm build`）
3. 在 staging 走 smoke test 关键路径

### 2.2 升版本

按 SemVer：

- **Patch**（0.0.X）：bug 修复 / 文案 / 样式
- **Minor**（0.X.0）：新增功能（兼容）
- **Major**（X.0.0）：破坏性变更

执行：

```bash
pnpm version <patch|minor|major>
# 触发 husky → 自动更新 CHANGELOG
git push --follow-tags
```

### 2.3 部署

- Vercel 检测到 `vX.Y.Z` tag → 部署到生产
- 部署完成后 Vercel 通知 + 群内贴链接

### 2.4 验证

主理人 5 分钟 smoke test：

- [ ] 首页 / KB 总览 / KB 详情 / 搜索 / 定价 / 登录 可访问
- [ ] 一个核心流程（注册 → 选套餐 → 支付 → 会员内容）
- [ ] 暗色模式无错位
- [ ] Sentry 无新错误
- [ ] 监控指标无异常

### 2.5 公告

- 公众号发"vX.Y.Z 更新说明"
- 邮件通知活跃会员
- 站内横幅（如有重大变化）

### 2.6 收尾

- GitHub Release：粘 CHANGELOG + 截图
- 关闭对应 milestone
- 在 `memory/历史经验.md` 记录（如有教训）

## 3. Hotfix 流程

紧急修复走 `hotfix/<short>` 分支：

1. 从 `main` 拉分支
2. 修复 + 测试
3. PR 走快速 review（1 名）
4. 合入 `main` + tag
5. Vercel 自动部署
6. 回灌 `develop`

## 4. 回滚

- 应用层：Vercel Dashboard → "Promote Previous"
- 数据库：见 [`docs/04-ops/备份与恢复.md`](../docs/04-ops/备份与恢复.md)
- 配置：Vercel Environment Variables 历史

详见 [`docs/04-ops/事故响应.md`](../docs/04-ops/事故响应.md)。

## 5. 验收

- [ ] CHANGELOG 更新
- [ ] Tag 已推
- [ ] 生产部署成功
- [ ] Smoke test 通过
- [ ] 公告已发
- [ ] 监控无异常

## 6. 反模式

- ❌ 不升版本直接发
- ❌ CHANGELOG 与代码不一致
- ❌ 跳过 staging
- ❌ 周末大版本
- ❌ 没有回滚预案

## 7. 速查

| 任务 | 命令 / 文件 |
|---|---|
| 升版本 | `pnpm version <level>` |
| 看 changelog | `CHANGELOG.md` |
| 部署 | Vercel → Production |
| 回滚 | Vercel → Deployments → Promote |
