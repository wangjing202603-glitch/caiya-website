# 技能：调整设计令牌

> 适用：设计负责人 + 前端工程师
> 目标：改设计令牌（颜色 / 字体 / 间距 / 阴影）有标准流程，避免"散点硬编码"导致不一致。

## 1. 触发场景

- 品牌色微调
- 字号 / 行高 / 间距调整
- 新增语义色 / 主题
- 暗色模式体验优化

## 2. 前置

- 阅读 [`docs/02-design/设计令牌.md`](../docs/02-design/设计令牌.md) 与 [`docs/02-design/设计系统总览.md`](../docs/02-design/设计系统总览.md)
- 评估影响面（哪些页面 / 组件 / 暗色模式）

## 3. 流程

### 3.1 评估影响

1. 用 `rg '#2D6BFF'`（待改色）等命令查"硬编码"违规
2. 用 `rg 'p-[0-9]'`、`rg 'text-(xs|sm|base|...)'` 找可能的字面值
3. 列出受影响的文件 / 页面
4. 评估"如果改了，可能引发的视觉问题"

### 3.2 在 `设计令牌.md` 改

1. 改对应取值 + 顶部"最后更新"
2. 写变更理由（一句）

### 3.3 同步到代码

1. 改 `tailwind.config.ts` 的 `theme.extend`
2. 改 CSS 变量（在 `app/globals.css`）
3. 改 shadcn/ui 的 theme 配置（如启用 `cssVariables`）

### 3.4 改组件

1. 用设计令牌的 class（`bg-brand-500` 而非 `bg-[#2D6BFF]`）
2. 跑 `pnpm lint` 看硬编码警告
3. 视觉回归（Playwright snapshot）

### 3.5 验证

- 桌面 + 移动 + 暗色 + 打印
- 关键页面：首页 / KB 总览 / KB 详情 / 定价 / 账户中心
- 关注点：
  - 对比度（用 axe / Lighthouse）
  - 视觉层级（标题 vs 正文）
  - 暗色模式是否有"亮斑"
  - 焦点环是否清晰

### 3.6 ADR

- 涉及"品牌色 / 主色"变更 → 写 ADR
- 写在 `memory/decisions/ADR-XXXX-token-change.md`

### 3.7 CHANGELOG

- 在 "变更" 区加一行

## 4. 验收

- [ ] 没有新增硬编码
- [ ] axe / Lighthouse 无 regression
- [ ] 视觉回归测试通过
- [ ] 文档同步
- [ ] 设计师 review

## 5. 反模式

- ❌ 改令牌但不更新文档
- ❌ 跳过影响面评估
- ❌ 在 `app/` 内联颜色（应该走组件层）
- ❌ 暗色模式没测

## 6. 速查

| 任务 | 工具 |
|---|---|
| 查硬编码 | `rg '#2D6BFF'`、`rg 'text-\[?[0-9]'` |
| 视觉回归 | `pnpm test:visual` |
| 暗色 | `next-themes` + axe |
| 设计令牌 | `docs/02-design/设计令牌.md` |
